# Minefed Display 가림 판정 수정 — 2026-09-24

Minecraft 1.20.4 / Fabric / Java 17 클라이언트에서 TV와 자유 크기 화면이
앞쪽 블록을 뚫고 보일 수 있는 렌더링 경로를 수정했다.

## 확인한 원인

두 블록 엔티티 렌더러는 `Tessellator`로 화면을 즉시 그리면서 깊이 검사와 깊이 쓰기를
명시하지 않았다. Minecraft 1.20.4의 `RenderPhase.DepthTest` 종료 코드가 깊이 검사를
끄는 것을 로컬 Minecraft 바이트코드에서 확인했다. 따라서 앞서 그려진 렌더 레이어의
상태에 따라 화면과 테두리가 월드의 가림 판정을 무시할 수 있었다.

## 수정

TV 화면, 자유 크기 화면과 테두리를 월드의 `VertexConsumerProvider`와 전용
`RenderLayer`로 그리도록 변경했다. 각 레이어는 `LEQUAL_DEPTH_TEST`와 `ALL_MASK`를
지정해 앞쪽 불투명 블록의 깊이와 비교하고 화면 자체의 깊이도 기록한다.
브라우저 텍스처는 해당 레이어를 실제로 그릴 때 바인딩한다.

기존 모드 버전, 저장 데이터와 네트워크 프로토콜은 유지한다. 운영 기준본 JAR는 보존하고
새 산출물의 해시와 소스 커밋은 별도 빌드 기록에 남긴다.

## 소스와 검증

- 추적 브랜치: `codex/fix-display-depth`
- 최종 커밋: `a1e8f94df20c22c1ccfc4083b1dc01dc7f757e45` (origin에서 확인)
- 렌더링 수정 커밋: `946a740dcea8964c0fd35c9c71a2b7ba29255891`
- 일반 `build`: 통과. 헤드리스 빌드는 OpenGL 검증을 요구하지 않는다.
- 선택적 `verifyDisplayOcclusion`: 숨김 GLFW 컨텍스트의 실제 깊이 버퍼에서 통과.
  기존 깊이 검사 누락의 재현 대조군, 벽 뒤 화면 가림, 벽 앞 화면 표시, 화면 뒤에 나중에
  그린 물체의 가림, 흰색 shaderColor 초기화를 검사했다. 테스트는 실제 수정된 레이어의
  상태 설정을 사용하며 Fabric 접근 변환을 초기화하지만 게임과 MCEF는 시작하지 않는다.
- 독립 코드 검토에서 TV/자유 크기 화면/테두리의 레이어 사용, 기존 좌표와 UV 보존,
  테두리 알파 블렌딩 보존을 확인했다.

실제 클라이언트팩의 Sodium·Indium·MCEF 조합과 그래픽 모드별 게임 내 검증은 수행하지
않았다. 적용 후에는 두 화면 종류의 앞에 불투명 블록을 놓고 네 방향에서 확인하며,
여러 블록 크기의 화면, URL 없는 테두리, 서로 겹치는 화면도 확인한다.

수정된 클라이언트 JAR로 교체하고 게임을 다시 시작해야 적용된다.
운영 서버 파일 교체나 재시작은 수행하지 않았다.
