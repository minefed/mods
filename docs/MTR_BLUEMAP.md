# MTR 실시간 교통 지도

Minecraft 1.20.4 / Fabric의 MTR 4.0.5와 BlueMap 5.3 기반 Minefed 빌드를
연결한다. MTR이 BlueMap 웹앱에 표시 스크립트를 등록하고, 각 월드의
시뮬레이션에서 읽은 선로·차량·노선·역 데이터를 웹 루트에 제공한다.
Minecraft 클라이언트의 접속 여부와 관계없이 서버의 차량을 읽되, 공개 설정에서
선택한 노선에 속하는 차량만 웹에 제공한다. 초기 공개 목록은 비어 있다.

## 공개 노선과 운행 계통 묶기

두 파일은 서버의 `config/mtr/`에 위치한다.

| 파일 | 용도 | 관리 주체 |
| --- | --- | --- |
| `bluemap-routes.json` | 월드별 전체 노선 ID·이름·색상·MTR 숨김 상태, 역 ID·이름·경유 노선 ID | 모드가 자동 갱신 |
| `bluemap-public-routes.json` | 공개 노선·운행 계통 그룹, 운영사, 간접환승 연결 | 서버 관리자가 편집 |

처음 시작하면 공개 설정은 다음과 같이 만들어진다. 이 상태에서는 열차·노선·역·
입체 선로가 공개되지 않는다. 전체 노선·역 목록 파일은 웹 루트에 복사하지 않는다.

```json
{
  "schema": 1,
  "worlds": {}
}
```

서버를 시작한 뒤 자동 갱신된 `bluemap-routes.json`에서 `worldId`와 노선의 `id`를
복사한다. ID는 숫자로 바꾸지 않고 따옴표로 감싼 문자열 그대로 사용한다.
다음은 가상의 ID를 사용한 설정 예시다.

```json
{
  "schema": 1,
  "worlds": {
    "minecraft/overworld": {
      "routes": ["300"],
      "groups": [
        {
          "id": "jungang",
          "name": "중앙선",
          "color": "#2B8C72",
          "routeIds": ["100", "200"]
        }
      ]
    }
  }
}
```

이 예에서는 `300`번 노선을 개별 공개하고, `100`번 일반열차와 `200`번 쾌속열차를
하나의 **중앙선**으로 묶어 공개한다. 그룹의 멤버를 `routes`에 다시 넣지 않는다.
그룹은 범례·경로·역의 노선 배지에서 한 노선으로 나타나고, 열차도 그룹 이름과
색상을 사용한다. 각 계통의 서로 다른 경로와 정차역은 함께 표시한다.
`color`를 생략하면 `routeIds` 첫 번째 노선의 MTR 색상을 사용한다.
그룹 아래에는 원래 MTR 노선 이름을 운행 계통으로 표시하므로, 일반·쾌속·급행
이름을 구별할 수 있다. 열차 상세와 역 도착 정보에도 해당 운행 계통을 표시한다.

### 계통 이름, 여러 원본 노선 묶기, 이름 표시 여부

그룹 안에 `services`를 사용하면 여러 MTR 노선을 하나의 운행 계통으로 표시할 수
있다. 다음 예시에서는 공항선 일반 계통의 이름은 숨기고, 중앙선은 일반과 쾌속을
표시한다. 중앙선 쾌속의 두 원본 노선은 하나의 계통 배지로 나타난다. ID는 예시이며
자동 목록에 있는 실제 값으로 바꾼다.

```json
{
  "schema": 1,
  "worlds": {
    "minecraft/overworld": {
      "routes": [],
      "groups": [
        {
          "id": "airport",
          "name": "공항선",
          "services": [
            {"id": "local", "name": "일반", "routeIds": ["300"], "showName": false}
          ]
        },
        {
          "id": "jungang",
          "name": "중앙선",
          "services": [
            {"id": "local", "name": "일반", "routeIds": ["100"], "showName": true},
            {"id": "rapid", "name": "쾌속", "routeIds": ["200", "201"], "showName": true}
          ]
        }
      ]
    }
  }
}
```

- `services[].id`: 해당 그룹 안에서 고유한 식별자. 영문 소문자·숫자로 시작하고
  영문 소문자·숫자·`_`·`-`를 사용하며 최대 64자다.
- `name`: 지도에서 사용할 계통 이름. 원래 MTR 이름은 변경하지 않는다.
- `routeIds`: 같은 계통으로 묶을 실제 MTR 노선 ID. 포함된 노선은 자동 공개된다.
- `showName`: 기본값은 `true`. `false`이면 범례·역 배지·열차 상세·도착 목록에서
  계통 이름을 숨긴다. 노선 그룹 이름, 차량, 경로, 도착 정보는 계속 표시한다.

`services`로 옮긴 ID를 그룹의 기존 `routeIds`나 다른 계통에 중복 기입하지 않는다.
계통에 넣지 않은 직접 멤버를 그룹의 `routeIds`에 함께 둘 수는 있다. 그룹 색상을
생략하면 직접 멤버의 첫 노선, 직접 멤버가 없으면 첫 계통의 첫 노선 색상을 사용한다.
같은 계통으로 묶어도 서로 다른 열차나 도착 정보는 한 건으로 합치지 않는다.

기존의 그룹 `routeIds`만 사용하는 설정도 계속 지원한다. 직접 멤버의 이름만
바꾸려면 해당 그룹에 `"routeNames": {"100": "일반", "200": "쾌속"}`을 추가할 수
있다. 생략한 ID는 원래 MTR 이름을 사용한다. 이름 표시 여부나 여러 ID를 묶는
기능이 필요하면 `services`를 사용한다. `routeNames`에는 직접 멤버만 지정할 수 있다.

### 운영사와 간접환승역

운영사는 공개 설정 최상위의 `operators`에서 별도로 관리한다. 각 노선 그룹의
`operatorId`는 이 목록의 키를 참조한다. 특정 원본 MTR 노선에만 다른 운영사를
지정하려면 월드의 `routeOperators`를 사용한다. `routeOperators`가 그룹의
기본값보다 우선하며, 그룹의 직접 `routeIds`와 `services[].routeIds` 모두에
적용된다. 개별 공개 노선에도 같은 방법으로 운영사를 지정한다.

MTR에서 서로 다른 역으로 등록된 간접환승역은 월드의 `interchanges`에서
역 ID로 연결한다. 다음 설정은 **모두 가상의 이름과 ID**를 사용한 완전한 예시다.
[`examples/mtr-bluemap-public-routes.example.json`](../examples/mtr-bluemap-public-routes.example.json)에도
같은 예시를 제공한다. 실제 서버의 기존 공개 설정에 필요한 항목을 합쳐 적용한다.

```json
{
  "schema": 1,
  "operators": {
    "example-rail": {"name": "예시철도"},
    "example-transit": {"name": "예시교통"}
  },
  "worlds": {
    "minecraft/overworld": {
      "routes": ["300"],
      "routeOperators": {
        "201": "example-transit",
        "300": "example-transit"
      },
      "groups": [
        {
          "id": "example-line",
          "name": "예시선",
          "color": "#2B8C72",
          "operatorId": "example-rail",
          "services": [
            {"id": "local", "name": "일반", "routeIds": ["100"], "showName": true},
            {"id": "rapid", "name": "쾌속", "routeIds": ["200", "201"], "showName": true}
          ]
        }
      ],
      "interchanges": [
        {
          "id": "example-transfer",
          "name": "예시 환승역",
          "stationIds": ["1000", "2000"]
        }
      ]
    }
  }
}
```

위 설정에서 `100`·`200`번 노선은 예시철도, `201`·`300`번 노선은 예시교통으로
표시한다. 같은 쾌속 계통에 묶인 `200`·`201`번도 실제 원본 노선에 지정된
운영사를 유지한다. 운영사 이름은 노선 범례, 역·열차 상세와 도착 정보에 표시한다.
운영사를 지정하지 않은 노선에는 운영사 표기를 추가하지 않는다.

- `operators`의 키와 `interchanges[].id`는 영문 소문자·숫자로 시작하며
  영문 소문자·숫자·`_`·`-`만 사용하고 최대 64자다. 이름은 공백만으로 만들 수
  없고 최대 256자다. 환승 연결의 ID는 해당 월드 안에서 고유해야 한다.
- `routeOperators`의 키는 공개 대상으로 선택한 **원본 MTR 노선 ID**다.
  그룹 ID나 계통 ID를 넣지 않는다. 운영사 지정 자체로 노선이 공개되지는 않는다.
  참조하는 운영사는 반드시 `operators`에 등록되어 있어야 한다.
- `stationIds`에는 해당 월드의 카탈로그에 있는 서로 다른 역 ID를 2개 이상
  넣는다. 역 하나를 여러 환승 연결에 중복 지정하거나 다른 월드의 역을 연결할
  수 없다. 노선·역 ID는 따옴표로 감싼 10진수 문자열을 그대로 사용한다.
- 이름이 같아도 자동으로 역을 합치지 않는다. 공개 노선이 지나는 역만 환승
  연결에 포함하며, 비공개 역의 ID·이름·노선은 웹에 노출하지 않는다.
  공개된 연결 역이 2개 미만으로 남으면 해당 간접환승 표시를 없앤다.
- 연결한 역은 각각의 위치에서 환승역으로 표시한다. 역 상세의 연결 역 선택
  버튼으로 다른 역을 선택할 수 있다. 원래 MTR 역, 승강장, 열차, 도착 예정은
  각각 유지하므로 간접환승 설정으로 도착 정보를 한 역에 합치지 않는다.

수인역처럼 같은 이름으로 등록된 역을 연결하려면, 갱신된 비공개
`bluemap-routes.json`에서 해당 월드의 `stations`를 확인한다. 각 항목은
`id`, `name`, `routeIds`를 제공한다. 같은 이름의 역들을 `routeIds`의 경유 노선과
대조해 구별하고, 확인한 실제 역 ID들을 한 `interchanges` 항목에 넣는다.
운영사 이름과 소속 노선도 서버 관리자가 확인해 등록한다.

추가 항목은 모두 선택 사항이며 `schema`는 계속 `1`이다. 기존 공개 설정은
수정 없이 사용할 수 있다. 운영사·환승 설정도 아래의 약 2초 갱신 정책을 따르며,
없는 운영사·역 참조나 중복 환승 소속 등 잘못된 설정은 전체 미공개로 처리한다.
이 기능의 최초 적용에는 Minecraft 1.20.4 / Fabric / MTR 4.0.5용으로 빌드한
새 MTR JAR를 예정된 점검에 교체하고 서버를 재시작해야 한다. 이후 설정만
편집할 때는 재시작이 필요하지 않다. 웹 스크립트만 교체해서는 서버의 운영사·역
데이터와 설정 처리가 추가되지 않는다.

운영사·간접환승 기능의 빌드, Java 17 검사, 데스크톱·모바일 시험 화면 검증과
배포 JAR 해시는
[`inventory/mtr-bluemap-operators-2026-10-14.json`](../inventory/mtr-bluemap-operators-2026-10-14.json)에 기록한다.

공개 파일이 BlueMap의 공개 기준이다. MTR에서 숨긴 노선도 여기에서 명시적으로
선택하면 공개할 수 있다. 선택하지 않은 노선, 노선 정보가 없는 차량, 비공개
노선만 운행하는 역과 선로는 서버의 공개 JSON에서 제외한다. 공용 선로와 공용역은
공개 노선에 해당하는 정보만 포함한다.

설정은 약 2초마다 확인하므로 정상적인 편집에는 재시작이 필요하지 않다. 변경을
감지하면 기존 공개 데이터를 먼저 비우고 새 설정으로 다시 생성한다. 형식 오류나
중복된 노선 지정 등 잘못된 설정은 로그에 기록하고 전체 미공개로 처리한다.
자동 목록은 약 30초마다 갱신하며, 공개 설정 파일은 자동 갱신으로 덮어쓰지 않는다.

## 표시 방식

- 선로는 MTR의 실제 곡선과 높이를 따라 입체적으로 표시한다.
- 열차는 각 차량의 실제 길이·폭과 개별 위치·방향을 가진 간소화한 3D 차체로
  표시한다. 편성 전체를 한 직선으로 그리지 않으므로 곡선에서 차량별로 방향이 달라진다.
- 열차 색상은 공개 노선 또는 그룹의 대표 색상을 사용한다. 현재 노선이 없으면
  다음 노선으로 공개 여부를 확인하며, 둘 다 없으면 표시하지 않는다.
- 차량기지에서 주박·대기 중인 편성은 표시하지 않는다. MTR의 운행 상태를 기준으로
  판단하므로, 운행 중인 열차가 역에 정차해 속도가 0이 되어도 계속 표시한다.
  아직 출발하지 않은 운행의 시간표상 도착 예정은 유지한다.
- 노선 경로는 생성된 MTR 운행 경로를 따라 그린다. 아직 생성되지 않았거나
  승강장 쌍과 연결할 수 없는 구간을 임의의 직선으로 이어 그리지 않는다.
- 역 POI를 선택하면 역 이름, 경유 노선과 운행 계통, 다음 도착 열차를 표시한다.
  공유역은 여러 노선을 함께 담으며, 선택한 공개 노선에 속하는 정보만 표시한다.
- 멀리서 보면 열차는 노선 색상의 위치 표식으로 전환한다. 노선 범례와 열차·선로·
  노선·역 레이어를 제공하며, 같은 선로를 공유하는 노선 색상은 나란히 표시한다.
- 우측의 밝은 카드에서 레이어와 노선을 확인한다. 역·환승 POI 또는 열차를 직접
  선택해 상세 정보를 보며, 주변 차량 선택 목록은 제공하지 않는다.

원본 차량의 차체 모델·도색 텍스처·문 애니메이션은 재현하지 않는다.
리소스팩의 모든 활성 차량 등록을 이름과 규격 목록에 포함하고, 운행 중의
차량은 공개 노선에 속하면 목록에 없는 ID라도 기본 표시를 제공한다. 실제 배치의 길이와 폭은
서버의 편성 데이터를 우선한다.

## 리소스팩과 빌드

서버팩 생성 시 배포할 리소스팩에서 차량 등록 목록을 추출해
`config/mtr/bluemap-vehicles.json`을 포함한다. 활성 등록 파일과 참조 자원을
검사하므로 차량을 추가하거나 변경한 뒤에도 같은 빌드 과정으로 목록을 갱신한다.
도색 이미지를 분석하거나 차량 모델·텍스처를 웹용으로 복제하지 않는다.

MTR JAR에는 웹 표시 스크립트가 포함된다. BlueMap이 설치되지 않은 환경에서는
연동을 시작하지 않으며, BlueMap API를 필수 모드 의존성으로 추가하지 않는다.

## 데이터와 운영 반영

MTR의 시뮬레이션 스레드에서 스냅샷을 만들고 파일 기록은 별도 작업에서
수행한다. 서버 API의 수정용 명령을 브라우저에 노출하지 않는다. 웹앱은
위치 스냅샷 사이를 보간하며, 오래된 데이터로 열차를 계속 운행시키지 않는다.
차량 데이터는 약 0.5초마다 갱신하고 0.65초 보간 버퍼를 사용한다. 6초간 새
스냅샷이 없으면 차량을 숨기고 연결 끊김을 표시한다. 선로·노선·역과 차량 목록은
약 30초마다 갱신한다. 지하 노선 경로는 지도에서 식별할 수 있게 겹쳐 표시하지만,
근거리의 입체 선로와 차량은 지형에 가려질 수 있다.

역 도착 정보는 약 2초마다 MTR의 도착 조회에서 읽는다. MTR의 지연이 반영된
도착·출발 시각을 사용하고, 실시간 운행 예측과 시간표상 예정을 구분한다.
도착 후 아직 출발하지 않은 열차는 정차 중으로 표시한다. 도착 정보가 없거나
갱신되지 않으면 그 상태를 안내하며 열차 위치로 도착 시간을 임의 계산하지 않는다.
역마다 최대 8건을 표시한다. 같은 승강장·차량기지를 매우 많은 비공개 계통과
공유하는 경우, Core 조회 상한으로 일부 도착 정보가 생략될 수 있다.

BlueMap 웹 루트 아래 `mtr-live/`에 지도별 연결 목록, 차량 위치, 선로·노선·역,
차량 이름·규격 목록이 생성된다. 외부 웹 서버로 지도를 제공한다면 이 디렉터리도
함께 제공해야 하며, 실시간 JSON에 장기 캐시를 적용하지 않아야 한다.

운영 반영 시 새 MTR JAR와 차량 목록 설정을 함께 배치하고 서버를 재시작한다.
같은 모드 ID의 이전 MTR JAR를 동시에 두지 않는다. 이 레이어는 BlueMap의
지형 타일과 독립적이므로 열차 이동을 반영하기 위해 지형을 강제 재렌더링할
필요가 없다. 지형·블록 모델에 관한 절차는 [BlueMap 안내](BLUEMAP.md)를 따른다.

연동을 끄려면 서버 JVM 인수에 `-Dmtr.bluemapLive.enabled=false`를 추가한다.
BlueMap이 비활성화되거나 MTR이 종료되면 실시간 데이터와 레이어 연결을 정리한다.

### 2026-10-13 웹 성능 수정

실시간 차량이 있으면 매 프레임 `viewer.redraw()`를 호출하던 동작을 제거했다.
이 호출은 BlueMap 전체 지형을 모니터 주사율에 맞춰 계속 그리게 만들어, 화면을
움직이지 않거나 열차가 화면 밖에 있어도 BlueMap의 유휴 렌더 제한을 해제했다.
수정 후에는 BlueMap의 기본 유휴 렌더 주기(약 20 FPS 이하)에서도 열차 위치를
보간하고, 지도 조작 시에는 BlueMap의 기존 고속 렌더링을 사용한다.

선로·노선·역 내용이 같으면 30초 갱신 때 기존 GPU 객체와 역 표시를 유지한다.
실제 내용이나 공개 설정·지도가 바뀌면 다시 생성하며, 열차 마커의 이름과 색상도
변경된 경우에만 DOM에 반영한다. 초기 텍스처 로딩과 최초 선로 생성 비용은 남는다.

기존 MTR 실시간 연동을 사용하는 서버에서는 다음 두 방식으로 적용할 수 있다.

1. 즉시 적용: 실제 BlueMap 웹 루트의 `mtr-live/mtr-live.js`를 백업하고 수정본으로
   교체한 뒤 브라우저를 강력 새로고침한다. 외부 웹 서버나 CDN이 이 파일을
   캐시한다면 해당 파일의 캐시도 갱신한다. 지형 재렌더링이나 서버 재시작은 불필요하다.
2. 영구 적용: 서버 정지 후 기존 MTR JAR를 수정 JAR로 교체하고 재시작한다.
   공개 노선 설정은 보존한다. 이전 JAR가 남으면 BlueMap 재연결·reload·서버 재시작 때
   이전 웹 스크립트를 다시 기록하므로, 웹 파일만 교체한 경우에는 이후 JAR도 교체한다.

이번 웹 수정에 BlueMap JAR나 리소스팩 교체, `force-update`는 필요하지 않다.
빌드·테스트·운영 응답 관찰의 구분과 산출물 해시는
[`inventory/bluemap-performance-2026-10-13.json`](../inventory/bluemap-performance-2026-10-13.json)에 기록한다.

저장소의 빌드·검사는 운영 서버 업로드나 재시작을 수행하지 않는다.

서버 ZIP의 `bluemap-public-routes.json`은 빈 초기 설정이다. 기존 서버에 업데이트할
때 직접 덮어쓰지 않는다. 별도 폴더에 압축을 풀어 파일을 배치하고, 동봉
`install-mods.py --directory <서버 폴더>`로 확인하면 기존 공개 설정은 보존하며
파일이 없는 경우에만 빈 기본 설정을 만든다. 기존 MTR JAR의 교체와 사용자 설정
보존은 별도로 수행한다.

지도 UI는 [Google Maps의 교통 레이어·역 아이콘 사용 흐름](https://support.google.com/maps/answer/3092439?hl=ko)을
참고한다. 외부 지도 서비스나 Google SDK를 연결하지 않고 BlueMap 위에서 동작한다.

## 검증 범위

서버 테스트는 실제 Transport Simulation Core 객체로 접속 플레이어 없이 차량을
열거하고, 차체 대차 위치·경사·길이·폭, 노선 색상, 실제 경로와 공유역을 검증한다.
웹 테스트는 보간, 누락·오래된 스냅샷, 지도 전환, 공유 노선과 자원 해제를 검사한다.
리소스팩 목록·서버팩 검사는 등록 누락, 자원 검증, 설정 해시와 사용자 수정 보존을
확인한다. 원본 모델을 웹에 복제하는 기능은 포함하지 않는다.

`Minecraft-Transit-Railway/tools/bluemap/demo-server.cjs`는 실제 BlueMap의
Three.js·HtmlMarker·CSS2DRenderer로 합성 데이터 시험 화면을 제공한다.
브라우저 시각 검증은 이 시험 화면에서 수행했으며 운영 월드에서의 통합 운행
검증을 대신하지 않는다. 빌드 출처와 검사 결과는
[`inventory/mtr-bluemap-services-2026-10-12.json`](../inventory/mtr-bluemap-services-2026-10-12.json)에 기록한다.
