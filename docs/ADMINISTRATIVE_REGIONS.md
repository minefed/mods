# Minefed 행정구역

`minefed-regions`는 Minecraft 1.20.4 / Fabric Loader 0.18.4 이상 / Java 17용
서버·클라이언트 모드다. [공개 소스](https://github.com/minefed/minefed-regions)는
MIT 라이선스이며, 통합·추적 브랜치는 `minefed-1.20.4`다.

이 문서는 2026-10-13 Q&A에서 확정한 규칙과 구현 구성을 기록한다.
등록은 소스와 배포 입력 준비를 뜻하며 운영 서버 설치·API 배포·재시작을 뜻하지 않는다.
지역 데이터는 빈 상태에서 시작한다. 아래 주소 예시는 실제 영토 데이터로 등록하지 않는다.

## 주소와 소속

지역은 변경되지 않는 ID, 표시 이름, 상위 지역 하나, 경계를 갖는다.
국가·주·시·구·동을 고정된 개수의 열이나 필수 단계로 만들지 않는다.
따라서 다음 두 주소를 같은 자료 구조로 표현한다.

- 마인연방공화국 → 수인시 → 중구 → 운회동
- 마인연방공화국 → 연해주 → 청진시 → 강성구 → 인혁동

주소는 국가부터 현재 위치를 포함하는 가장 깊은 지역까지 이름을 이어서 표시한다.
`22` 같은 번지는 모드에서 관리하지 않으며 인게임 표지판으로 처리한다.
같은 부모 아래의 이름 중복은 금지한다. 수인시 중구와 청진시 중구처럼 부모가 다르면
같은 이름을 사용할 수 있다. 최상위 지역은 국가이며 국가끼리도 이름을 구별한다.

이 구조에서는 특별시·주·자치구 같은 명칭 때문에 불필요한 중간 지역을 만들 필요가 없다.
이름을 바꾸거나 상위 지역으로 옮겨도 지역 ID를 유지하므로 관리 이력과 연동 참조를 보존한다.
지도에서 어느 확대 수준에 보이는지는 주소상의 이름과 분리해 설정한다.

## 영토 규칙

- 일반 월드(`minecraft:overworld`)만 지원한다. 네더·엔드에서는 주소 HUD를 표시하지 않는다.
- X/Z 평면의 경계를 모든 높이에 적용한다. 같은 좌표의 지하·지상·상공은 같은 지역이다.
- 오목한 다각형, 떨어진 섬·월경지, 내부에 제외된 구멍을 지원한다.
- 국가 간 또는 같은 부모 아래 형제 지역 간의 내부 면적은 겹칠 수 없다. 경계선은 맞닿을 수 있다.
- 자식의 영토 전체가 부모 영토 안에 있어야 한다. 부모의 구멍 안에는 자식을 둘 수 없다.
- 자식을 벗어나게 하는 부모 경계 축소는 거부한다. 부모가 자동 확장되지는 않는다.
- 국가 밖이나 하위 지역으로 나누지 않은 공간을 허용한다.
- 하위 지역이 남아 있으면 부모를 삭제할 수 없다. 먼저 하위 지역을 삭제하거나 적합한 다른 부모로 옮긴다.

편집 중인 경계는 아직 적용된 영토가 아니다. 저장할 때 서버의 현재 데이터와 함께
경계 유효성·포함 관계·중복·권한을 검사한 뒤 한 변경으로 반영한다.
정확히 공유 경계선 위에 있을 때는 지역 ID 순서로 하나의 소속 경로를 선택해
주소가 서로 다른 국가·부모의 이름을 섞거나 프레임마다 바뀌지 않게 한다.

## 관리자 권한

전체 관리자는 Minecraft UUID로 명시적으로 지정한다. OP라는 이유만으로
행정구역 권한을 주지 않으며, 최초 전체 관리자 지정은 서버 콘솔에서 한다.
국가 생성·삭제와 전체 관리자 지정·해임은 전체 관리자용 작업이다.

지역 관리자는 자신이 맡은 지역의 **모든 하위 단계**를 관리한다.
허용 범위는 하위 지역 생성·삭제·이름·경계·소속 변경과 하위 관리자 임명·해임이다.
자기 지역의 이름·경계나 자기 지역 관리자 명단은 변경할 수 없다.
하위 지역이 없는 동의 관리자는 편집 대상이 없으며, 별도 관리자가 있는 하위 지역에도
상위 관리자의 관리 권한은 유지된다.

Q&A 초기의 직접 관리자 우선권·명령 우선순위·잠금 규칙은 사용자의 수정 답변에 따라
전부 폐기했다. 권한 범위 안의 관리자는 같은 검증을 거쳐 수정하며,
동시 편집 충돌은 버전 검사로 거부한다. 더 높은 관리자의 이전 변경을 자동 복원하지 않는다.
건축·파괴·상호작용·출입 제한 같은 게임플레이 보호 기능은 포함하지 않는다.

## 인게임 편집과 HUD

현재 버전은 인게임 선택 도구로 경계 지점을 찍고 명령어로 지역을 관리한다.
경계의 외곽·구멍·분리된 영토를 편집한 뒤 생성 또는 경계 변경 명령으로 저장한다.
정확한 명령 구문과 설정 파일은 [모드 사용 안내](../minefed-regions/README.md)를 따른다.

HUD 기본 위치는 우측 상단이다. 사용자별로 좌측·우측, 표시 여부와 글자 크기를
조절한다. 동까지 지정된 곳은 전체 주소를, 구까지만 지정된 곳은 구까지 표시한다.
어느 국가에도 속하지 않으면 `미지정 지역`으로 표시한다.

서버는 API 응답을 저장하고 HUD에 필요한 주소를 클라이언트에 전달한다.
API 연결이 끊기면 마지막 정상 데이터로 주소와 경계 표시를 유지한다.
변경 명령은 연결 복구 전까지 실패하며, 로컬 변경을 쌓았다가 자동으로 덮어쓰지 않는다.
최초 실행부터 데이터가 없으면 API에서 정상 데이터를 받은 것처럼 취급하지 않는다.

## BlueMap

BlueMap 설치 시 지역 이름·경계와 클릭 시 전체 주소를 2D·3D 지도에 표시한다.
멀리 볼 때 국가, 확대할수록 더 작은 지역을 볼 수 있도록 주소 트리 깊이를
기본 표시 단계로 사용한다. 지역별 표시 단계 재정의도 지원한다.
수인시는 기본적으로 국가 직속인 연해주와 같은 단계이고, 필요하면 청진시와
같은 확대 수준에 보이도록 조절한다.

이름에 붙은 `시` 같은 접미사로 단계나 관리 권한을 추론하지 않는다.
BlueMap에는 표시용 데이터만 제공하며 API 인증 토큰이나 관리자 정보를 공개하지 않는다.
지도와 HUD는 같은 지역 자료를 사용한다.

## API와 변경 이력

`minefed-api`의 PostgreSQL 데이터를 원본으로 사용하고, 기존 gRPC 서비스와 함께
행정구역용 HTTP 인터페이스를 제공한다. Minecraft 서버의 인증 토큰은 허용된
`worldId`에 묶으며, 플레이어 UUID는 Minecraft 서버가 확인한 값을 사용한다.
토큰은 서버 환경 변수로 공급하고 설정 파일에는 환경 변수 이름만 기록한다.
클라이언트 패킷·공개 지도·소스 저장소에는 토큰을 넣지 않는다.

수정 요청은 요청 ID와 기대 버전을 사용한다. 같은 요청 재전송으로 변경이 두 번
적용되는 일을 막고, 이미 다른 관리자가 수정한 버전을 덮어쓰지 않는다.
인게임 경계 작업본은 선택·불러오기 시점의 기준 버전을 보관한다. 그 뒤 변경이
생기면 최신 경계를 다시 불러오거나 변경을 검토하고 `select rebase`로 명시적으로
기준 버전을 갱신해야 저장할 수 있다.
이름·경계·소속·관리자 변경과 실행 주체를 감사 이력에 기록한다.
되돌리기도 새 변경이며 현재 권한, 버전, 이름 중복, 경계와 자식 포함 조건을 다시 검사한다.

향후 웹 관리 화면은 이 API와 검증을 사용하도록 준비한다.
현재 범위에는 웹 지도에서의 편집 UI, 런처의 관리 화면이나 별도 로그인 흐름은 포함하지 않는다.
API 설정·마이그레이션·HTTP 계약은 `minefed-api`의 행정구역 문서를 따른다.
운영 DB 마이그레이션과 서비스 배포는 운영 적용을 요청받은 뒤 별도로 수행한다.

이 모드와 함께 검증한 API 소스는 `minefed-api/main`의
[`ad407eb6df88ded90f2478db9371ce58b5e4d4e7`](https://github.com/minefed/minefed-api/commit/ad407eb6df88ded90f2478db9371ce58b5e4d4e7)이다.
해당 커밋의 [HTTP 계약](https://github.com/minefed/minefed-api/blob/ad407eb6df88ded90f2478db9371ce58b5e4d4e7/docs/REGIONS_API.md)은
명령, 인증, 감사 이력의 `beforeRevision` 커서를 기록한다. 원격 `main`에서 이 커밋을
확인했으며, 호환성 검증에 사용한 소스 식별자이지 운영 배포 버전이라는 뜻은 아니다.

## 빌드·출처·검증

새 모드는 `inventory/build-recipes.json`의 소스 빌드 대상이며 서버·클라이언트
릴리즈에 함께 포함한다. 소스 커밋·JAR SHA-256·SHA-512·크기와 MIT 고지는
`inventory/mods.lock.json`, `inventory/license-audit.json`, `inventory/notices/`에서 관리한다.
`inventory/release-inputs.json`은 검토한 LICENSE·README Git blob을 고정한다.

`capturedServerBaseline: false`로 등록하므로 2026-09-06에 관측한 JAR 70개와
그 원본 패키징 결과는 유지한다. 이 항목의 JAR는 이번 소스에서 빌드한 산출물이며
운영 서버에서 수집한 파일이 아니다. 외부 라이브러리·Minecraft·BlueMap JAR를
새 모드 안에 묶어 재배포하지 않는다.

검증한 빌드 JDK는 21이며 산출물의 게임 런타임은 Java 17이다.
개별 빌드는 모드 디렉터리에서 `gradlew.bat test remapJar` 또는
`./gradlew test remapJar`로 수행한다. 산출물은
`minefed-regions/build/libs/minefed-regions-1.0.0.jar`다.
통합 빌드·릴리즈는 기존 [빌드 안내](BUILDING.md)와 [릴리즈 안내](RELEASING.md)를 따른다.

자동 검사와 로컬 검증은 운영 데이터·플레이어를 대상으로 하는 검증과 구분한다.
운영 적용 전에는 API 연결, 최초 관리자 지정, 실제 선택 도구 사용, 경계 진입 HUD,
BlueMap 확대·클릭 표시와 장애 후 복구를 배포 환경에서 확인해야 한다.
