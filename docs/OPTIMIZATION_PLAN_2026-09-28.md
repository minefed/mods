# 모드팩 전체 네트워크·FPS 최적화 계획 — 2026-09-28

Minecraft 1.20.4 / Fabric 모드팩의 **서버 송신(TX)·수신(RX)**과 **클라이언트 FPS**를 줄이기 위한 계획이다.
**모든 항목의 전제는 기존 기능과 똑같이 동작하는 것이다.** 화면, 게임플레이, 플레이어가 보는 동기화 시점과 저장 데이터가 달라지면 안 된다.
이 문서는 계획이다. 구현 결과와 제외한 항목은 [구현 결과](OPTIMIZATION_RESULTS_2026-09-28.md)에 기록했다.

## 조사 범위와 방법

- 소스 서브모듈 50개를 모두 초기화했다. 비공개 `resourcepack`은 제외했다.
- 모드를 5개 영역으로 나눠 네트워크 송수신 경로, 서버 틱, 렌더 경로를 코드 단위로 읽었다.
  1. MTR·MSD·minefed-display·webstreamer
  2. PFM·Yuushya 2종·Handcrafted
  3. 표지판·장식 모드
  4. 기술·게임플레이 모드
  5. 인프라·최적화 모드
- 소스가 없는 번들 라이브러리는 로컬 임시 폴더에서 디컴파일해 확인했다. 대상은 MTR의 Transport-Simulation-Core와 Mappings, TrafficCraft의 DragonLib, DiagonalBlocks다.
- 기존 측정 자료도 반영했다. [2026-09-21 성능 진단](PERFORMANCE_DIAGNOSIS_2026-09-21.md), [MTR 3D 선로 최적화](MTR_RAIL_OPTIMIZATION_2026-09-21.md), MTR `docs/performance-optimizations.md`다.
  이미 적용된 MTR 바이너리 코덱, 도착 정보 캐시, 선로 묶음 처리, 화면 밖 선로 제외는 다시 제안하지 않는다.
- 이 조사에서는 빌드·게임 실행·패킷 측정을 하지 않았다. 아래 수치 중 측정값은 2026-09-21 기록뿐이다. 나머지는 코드에서 계산한 **추정치**이며, 단계별 실측으로 확인해야 한다.
- 수정 불가 대상은 다음과 같다. 이들은 설정·운영 조정만 다룬다.
  - 바이너리 전용 모드 13종: mcw 계열, PTS Deco, Exline, Furniture Expanded, Japan Props, Rechiseled, Fusion 등.
  - 공식 JAR로 쓰는 기반 라이브러리 7종: Fabric API, owo, Architectury 등.
  - 클라이언트 의존성: Sodium, Indium, Continuity, MCEF.

### 동등성 판정 기준

어떤 변경이든 다음 중 하나를 증명해야 채택한다.

- **같은 결과의 재사용:** 같은 입력에서 같은 결과를 다시 계산하지 않는다. 예: 블록 상태별 형태 캐시, 매 프레임 재생성하던 객체 재사용.
- **중복 전송 제거:** 클라이언트가 이미 가진 것과 바이트 단위로 같은 상태를 다시 보내지 않는다.
- **무시되는 전송 제거:** 받는 쪽이 무시하는 대상에게 보내지 않는다. 예: 해당 엔티티·청크를 추적하지 않는 플레이어.
- **같은 GL 출력:** 같은 GL 호출을 같은 순서로 내며, 할당·중복 바인딩만 줄인다.

패킷 형식을 바꾸는 항목은 따로 3단계로 분리했다. 서버와 클라이언트 팩을 같은 버전으로 함께 배포한다는 전제가 필요하다.

## 단계별 계획

각 항목은 모드별 작은 커밋으로 나눈다. 서브모듈 `minefed-1.20.4`(client-compat은 `main`)에 먼저 커밋한 뒤, 상위 저장소의 gitlink·lock을 별도 커밋으로 갱신한다([AGENTS.md](../AGENTS.md)).
"검증" 열의 도구는 0단계에서 준비한다.

### 0단계 — 측정 기반 (코드 변경 전)

1. **서버 패킷 통계:** 테스트 서버 전용 계측 모드를 `tools/`에 둔다. 패킷 종류·채널별 개수와 바이트를 압축 전후로 집계하고, 서버팩에는 넣지 않는다. 서버 틱은 spark 또는 `/carpet profile`로 MSPT를 기록한다.
2. **클라이언트 프레임:** 기존 방식대로 F3+L 10초 기록과 45초 JFR을 쓴다. 할당률, GC 정지, 렌더·작업 스레드 샘플을 본다.
3. **고정 시나리오 6개:** 월드, 좌표, 시야, 렌더 거리, 해상도, VSync를 고정한다.
   - MTR 비교 승강장 `(-590.5, 70, 52.5)`, 차량 정차 중
   - Townscape 거리와 몹
   - PFM 주방(조리 완료 음식, 샤워)
   - C&B 건축 지역에 플레이어 2명
   - 신호등 교차로
   - Oritech 공장
4. **동등성 확인:**
   - 블록 상태 전수 형태 비교 테스트
   - 패킷 페이로드 바이트 비교
   - 스크린숏 비교: 기존 `scripts/audit_creative_inventory.py`와 월드 장면 캡처
   - 재접속 후 상태 비교

### 2단계 — MTR 클라이언트 핵심 경로 (FPS, 중위험)

측정된 최대 병목이다. 공개 API와 렌더 순서를 유지하고, 기존 선로 최적화처럼 회귀 테스트와 배포 JAR 믹스인 검사를 함께 추가한다.

1. **문 개방 판정 캐시 (`canOpenDoors`):**
   - 루프가 방문하는 정수 칸 범위를 키로, "승강장 발견 여부"와 "잠금 해제된 PSD/APG 위치 목록"을 저장한다.
   - 클라이언트 믹스인이 청크별 epoch를 올려 캐시를 무효화한다. 대상은 `WorldChunk.setBlockState`에서 이전·새 블록이 승강장이나 PSD/APG인 경우, 그리고 청크 로드·언로드, 월드 교체다.
   - 캐시가 맞아도 `setDoorValue(doorValue)` 부수효과는 매 프레임 그대로 실행한다.
   - 검증: 무작위 블록 편집과 청크 언로드에서 캐시 결과와 원래 결과를 비교하는 테스트. 실제 게임에서 PSD/APG 개폐와 탑승 확인.
2. **가림 판정 작업 스레드:**
   - (a) 같은 바이트 배치를 쓰는 사용자 정의 `OcclusionCache`를 만든다. 0에서 바뀐 인덱스만 기록하고, 초기화 때 그 인덱스만 0으로 되돌린다.
   - (b) 판정 범위 정육면체와 겹치지 않는 AABB는 O(1)로 `false`를 반환한다. "카메라가 내부에 있으면 `true`" 검사는 먼저 유지한다.
   - 기존에도 결과가 −1로 건너뛰어지던 칸만 생략한다. 검증: 카메라·상자를 무작위로 배치해 기존 판정과 비교.
3. **Mappings `OptimizedRenderer`/`BatchManager` 할당 제거:**
   - `VertexAttributeType.values()`를 캐시한다.
   - 행렬을 `ByteBuffer` 없이 `glVertexAttrib4f`로 직접 넘긴다.
   - `MaterialProperties` 해시를 메모이즈한다.
   - 재질별 `ArrayList`를 풀로 재사용하되, 맵 순회 순서는 유지한다.
   - VAO가 같으면 다시 바인딩하지 않는다.
   - 검증: 같은 GL 호출을 같은 순서로 내는지 apitrace/RenderDoc으로 비교.
4. **MSD 가공전차선:** 구간 `BlockPos`를 미리 계산하고, 전차선 하나당 콜백 하나로 같은 순서의 정점을 내보낸다. 빛 값은 매 프레임 조회를 유지한다.

### 3단계 — 패킷 형식 변경 (서버·클라이언트 동시 배포)

형식이 바뀌면, 다른 버전 클라이언트에서는 해석 오류가 날 수 있다. 그래서 모드 버전을 올리고 서버·클라이언트 팩을 같은 릴리즈로만 배포한다.
MTR은 이미 쓰는 codec 협상 방식을 따라, 구버전 상대와는 기존 형식을 유지한다.

### 4단계 — 클라이언트 렌더러 심화 (FPS)

- **geckolib (Oritech 기계 모델):**
  - 큐브마다 `Matrix4f` 복사, 면마다 `Vector3f`, 정점마다 `Vector4f`, 회전 `Quaternionf` 3개를 새로 만든다. 이를 재사용 버퍼로 바꾸고, 회전이 0인 축은 건너뛴다.
  - 애니메이션 큐를 매 프레임 새로 만들지 않고 비워서 재사용한다.
  - 추정: 150큐브 모델 30개·100 FPS에서 약 400 MB/s 할당 제거(JIT 탈출 분석으로 일부 상쇄될 수 있어 JFR로 확인).
- **fabric-seasons:**
  - 바이옴을 조회할 때마다 문자열 변환, 거부 목록 탐색, 계절 계산 배열 할당, `Pair` 박싱이 일어난다. 틱별 계절 캐시와 바이옴별 적용 결과 캐시로 바꾼다.
  - 서버 설정을 수신하면 캐시를 초기화한다.
- **mishanguc:**
  - 텍스트 스타일 비교용 `boolean[5]` 할당을 없앤다.
  - 가운데·오른쪽 정렬 폭 계산을 텍스트·폰트 식별자 기준으로 캐시하고, 리소스를 다시 로드하면 초기화한다.
  - 화살표 사각형 목록을 캐시한다.
  - 색 블록 엔티티는 색이 바뀔 때만 청크를 다시 빌드한다.
- **TrafficCraft 렌더러:**
  - 전구마다 매 프레임 하던 키 객체 생성과 스트림 선형 탐색을 `EnumMap` 조회로 바꾼다.
  - 전구 텍스처를 하나의 아틀라스로 묶어 드로 콜을 줄인다. 아틀라스는 픽셀 비교로 검증하며 중위험이다.
  - 표지판 배경 텍스처가 이미 있으면 다시 만들지 않는다.
  - 서버 표지판 텍스처 NBT를 LRU로 캐시한다.
- **minefed-display:** 베젤 쿼드를 텍스처별로 모아서 그린다. 같은 평면에서 겹치지 않는 쿼드라 결과 이미지가 같다. 디스플레이 폭이 W일 때 약 2W회이던 드로 콜이 레이어 수 수준으로 준다.
- **webstreamer:**
  - `grabRemaining`에서 버릴 영상 프레임까지 디코딩하지 않는다(`grabSamples`).
  - 층마다 문자열을 만들던 프로파일러를 `DummyProfiler`로 바꾼다.
  - 디코딩을 작업 스레드로 옮기는 것은 과부하 때 멈춤 대신 이전 프레임을 보여 주게 되어 체감 동작이 달라진다. 그래서 별도 판단 항목으로 둔다.
- **PFM:** 모든 블록의 청크 렌더 타입 조회에 붙은 취소 가능 `@Inject`를 `@ModifyReturnValue`로 바꾸고, 블록별 판정을 메모이즈한다. 청크 빌드 작업 스레드의 `HashMap` 경쟁 상태도 해소된다.

### 5단계 — 운영 설정 (코드 변경 없음)

운영 서버 파일 변경은 별도 요청이 있을 때만 수행한다. 여기서는 권장안만 적는다.

- **Velocity 뒤 백엔드 압축:**
  - 플레이어 연결은 Velocity가 압축한다. 따라서 백엔드와 Velocity가 같은 호스트나 LAN에 있다면, 백엔드 `network-compression-threshold=-1`로 압축 해제·재압축 비용을 없앨 수 있다.
  - 플레이어가 받는 바이트는 같다.
  - 플레이어 방향 전송량을 더 줄이려면 Velocity `compression-level`을 조정한다. 이 경우 CPU를 더 쓴다.
- **BlueMap:** `render-thread-count`를 물리 코어 여유에 맞춘다. Chunky로 미리 생성하는 동안에는 렌더를 일시 중지한다. 지도 갱신 시점만 달라지고 게임플레이는 같다.
- **Carpet scarpet:** 서버 `world/scripts`에 매 틱 패킷을 보내는 앱이 있는지 점검한다.
- **ModernFix:** lock은 5.17.0인데 2026-09-21 측정 클라이언트는 5.17.1-beta.4였다. 버전을 정리한다.
  `mixin.perf.faster_item_rendering`은 동등성이 증명되지 않았다. 크리에이티브 인벤토리 감사 도구로 켰을 때와 껐을 때를 비교해 차이가 없을 때만 채택한다.
- **Lithium·FerriteCore·Starlight:** 추가로 켤 수 있으면서 동작이 같다고 증명된 옵션은 없다. 기본값을 유지한다.
- **선택 사항:** Krypton 0.2.6(LGPL-3.0, 1.20.4 지원)은 백엔드 자체 압축과 flush를 최적화한다. Velocity 설정 조정을 적용하면 효과가 거의 없고 FabricProxy-Lite와의 호환성도 확인되지 않았다. 따라서 모드 목록 변경으로 따로 판단한다.

## 부수 발견 (최적화 범위 밖, 별도 작업 권장)

- **TimeOutOut (추정, 디컴파일 확인 필요):** 1.20.2 이후 keep-alive 처리는 공통 네트워크 핸들러로 옮겨졌다. 그런데 `ServerPlayNetworkHandler.tick`의 `60L` 상수를 바꾸는 믹스인은 그대로다. 이 상수가 `player-idle-timeout`의 분→밀리초 계수라면 잠수 추방 시간이 크게 늘어난다.
- **권한·거리 검증이 없는 C2S 처리:**
  - PFM `TOILET_USE`
  - Yuushya Modelling `TransformDataOncePacket`
  - minefed-display의 URL·크기 변경

  로드된 아무 블록이나 조작할 수 있으므로 보안 점검이 필요하다.
- **minefed-client-compat:** PTS Deco·PFM·DragonLib의 정확한 버전에 의존하고, 믹스인이 `required: true`다. 바이너리 전용 모드용 최적화 믹스인을 추가한다면, 대상 모드가 있을 때만 적용하도록 별도 설정(`required: false`와 플러그인 조건)으로 분리해야 한다.
