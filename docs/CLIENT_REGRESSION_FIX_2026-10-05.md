# 클라이언트 성능·커서 회귀 수정 — 2026-10-05

Minecraft 1.20.4 / Fabric 클라이언트의 최근 최적화 이후 성능 저하와 게임 중
커서 이탈 신고를 조사했다. 확인된 가림 판정 캐시의 CPU 회귀와 월드 웹
디스플레이의 커서 잠금 해제 경로를 수정한다. 실제 게임의 전후 FPS 개선이나
모든 끊김의 해소를 확인한 보고서는 아니다.

## 조사한 실행 환경

- Modrinth `client` 프로필의 배포 버전은 `20260930181902`였다. 설치 명세와
  MTR·MSD·display·webstreamer·client-compat·Sodium JAR의 SHA-256이 일치했다.
- MTR 소스는 `0650f2699f7860a119da5f78edfb1c3c492a79ee`, display 소스는
  `30cad66e155323a87b15dadf63ccc89be92ecd89`, client-compat은 1.4.0이었다.
- Java 17, 최대 힙 6 GiB, 렌더/시뮬레이션 거리 12/12, VSync 켜짐,
  최대 60 FPS, 창 모드였다. 블록 아틀라스는 `8192x4096x4`로 축소가 적용됐다.
- 22:33:17~22:33:47 KST의 30초 JFR을 수집했다. 수집 직후 게임은 배경 창이었다.
  따라서 이 기록을 전경 플레이 FPS 또는 이전 장소의 FPS 기록과 비교하지 않는다.

Java 실행 표본은 MTR 가림 판정 작업 스레드 1,631개, 렌더 스레드 275개였다.
작업 스레드에서는 블록 상태 조회가 컸고, 렌더 스레드에서는 MTR·MSD 전차선
렌더링 경로가 관측됐다. 표본 개수를 전체 CPU 시간 비율로 해석하지 않는다.
GC 정지는 2회, 합계 9.32ms, 최대 5.00ms로 이 구간에서 긴 GC 정지가 주요
원인이라는 근거는 없었다. 운영 서버 TPS/MSPT는 측정하지 않았다.

원시 JFR·설치 명세·프로파일 분석은 Git에서 제외한
`.cache/performance/20261005-regression/`에 보존한다.
JFR의 한글 임시 경로 문제로 수집 때 ASCII 임시 폴더를 사용했다. 활성 기록과
임시 드라이브는 정리했으나 원래 경로로의 복원도 인코딩 오류로 거부되어,
현재 JVM의 JFR 임시 저장 위치만 `C:/Users/Public/minefed-diagnostics-20261005/`
아래에 남는다. 게임 재시작 후에는 이 일회성 JVM 설정이 유지되지 않는다.

## 마우스 커서

MCEF 2.1.6의 기본 페이지 커서 리스너는 `glfwSetInputMode`로 게임 창의 커서를
`NORMAL` 또는 `HIDDEN`으로 바꾼다. 월드 안 디스플레이에도 이 리스너가 설치돼
있어 Minecraft의 `DISABLED` 잠금을 풀 수 있었다. 실행 로그에도
`65539: Invalid standard cursor 0x00000000`이 기록됐다. MCP 제어 모드는 꺼져 있었다.

`minefed-display` 1.0.1은 TV와 사용자 크기 디스플레이 모두 공통 팩토리를 통해
**네이티브 브라우저 생성 전에** 커서 이벤트를 무시하도록 한다. MCEF 초기화 검사,
종료 허용, 생성·이동·크기 변경 동작은 유지한다. 다른 모드가 만든 대화형
브라우저의 커서 처리는 바꾸지 않는다.

검증은 실제 고정 MCEF 바이트코드의 커서 변경 호출 확인, 컴파일된 두 렌더러의
공통 팩토리 사용 확인, 생산 코드 팩토리에 생성·이동·크기 변경 중 커서 이벤트를
발생시키는 경계 테스트로 구성했다. 기존 베젤 렌더링 검사도 통과했다.
이 검사는 실제 Chromium 페이지를 띄운 게임 플레이 검증과 구분한다.

## 성능 수정 범위

9월의 MTR 메모리 최적화는 모든 거리에서 희소 캐시를 사용하도록 바꿨다.
메모리는 줄지만 가림 판정의 각 광선 셀 조회에 추가 주소 계산·배열 조회가 필요했다.
고정 occlusionculling 라이브러리로 같은 AABB·카메라·캐시 초기화 순서를 실행해
이 CPU 비용 증가를 재현했다. 실제 작업 스레드에서는 블록 조회 비용도 크므로
캐시 회귀 하나로 신고된 전체 저하를 설명하지 않는다.

수정은 렌더 거리 16 이하에서 이전에 검증된 연속 배열과 변경 블록 초기화 방식을
사용하고, 그보다 큰 거리에서는 기존 희소 캐시를 유지한다. 현재 거리 12의 배열
본체는 13.5 MiB, 거리 16에서는 32 MiB이며 작은 변경 추적 비트셋이 추가된다.
거리 32에서 256 MiB 전체 배열을 다시 할당하지 않는다. 월드를 나갈 때 캐시를
해제하는 기존 동작도 유지한다. 화질·렌더 거리·VSync·사용자 설정은 바꾸지 않는다.

가림 결과·바이트·초기화·잘못된 인덱스의 예외를 원본 라이브러리와 비교하고,
거리 12/16/17/32 및 경계에서 캐시 선택과 메모리 상한을 검사한다.
하위 저장소의 `:fabric:benchmarkOcclusionCache`는 수정 전 희소 정책과 실제
수정 후 캐시 선택을 각각 별도 JVM에서 비교하는 재현 도구다. 시간 상한을
단위 테스트 성공 조건으로 사용하지 않는다.

최종 Java 17 비교는 같은 입력의 AABB 512개를 한 묶음으로 삼아, 카메라 이동과
묶음마다 캐시 초기화를 포함하고 준비 실행 후 7회 측정의 중앙값을 사용했다.
두 정책은 각각 별도 JVM에서 실행했다.

| 거리 | 합성 장면 | 수정 전 희소 캐시 | 수정 후 실제 선택 | 판정 결과 |
| --- | --- | ---: | ---: | --- |
| 12 | 열린 공간 | 1.528ms | 1.077ms | 동일 |
| 12 | 기둥 | 4.688ms | 3.469ms | 동일 |
| 12 | 벽 | 31.320ms | 21.148ms | 동일 |
| 16 | 벽 | 23.084ms | 17.371ms | 동일 |

현재 거리 12의 이 합성 연산은 26.0~32.5% 빨라졌다. **FPS 개선율이 아니다.**
거리 17과 32는 동일한 희소 구현·할당 크기·판정 체크섬을 유지했다.
실행별 시간 차이는 같은 구현에서도 발생하므로 그 거리에서는 개선을 주장하지 않는다.
재현 결과는 `inventory/client-regression-fixes-2026-10-05.json`에도 기록한다.

## 검증

- MTR: `:fabric:test` 79건, `:fabric:verifyRailRendering` 8건,
  `:fabric:verifyMixinCompatibility` 8건, `:fabric:verifyLightTypeCompatibility` 3건 통과.
  JDK 21로 빌드하고 Java 17에서 검증했다.
- display: JDK 17 `build`, `verifyDisplayCursor`, `verifyDisplayBezelTrace` 통과.
  기존 베젤 검사는 13,552개 경우의 23,586,112개 꼭짓점을 비교했다.
  배포 JAR에 테스트용 MCEF 대역 클래스가 포함되지 않음을 확인했다.
- 상위 저장소: 빌드 도구 테스트 54건, 릴리즈 입력 테스트 17건 및 빌드 계획 검사 통과.
- 두 수정 모두 독립 코드 검토를 수행했다. MTR의 복원된 배열 구현은 이전에
  검증된 구현과 클래스 이름 외에 동일하며, MCEF 생성자와 콜백의 실제 바이트코드를
  확인해 첫 콜백 전에 리스너가 교체되는 것을 검토했다.
- MTR 배포 JAR의 리소스 경로 4,387개가 설치된 기준과 같았다. 달라진 리소스
  2,008개는 CRLF/LF 차이뿐이며 의미 차이나 추가·삭제는 없었다.

## 적용과 남은 실게임 확인

소스와 교체 JAR의 검증은 실행 중 클라이언트에 자동 적용되는 작업이 아니다.
게임을 종료한 후 기존 display JAR를 1.0.1로, MTR JAR를 이번 산출물로 교체하고
다시 실행해야 한다. 기존 파일과 해시를 먼저 백업하며 같은 모드의 이전 JAR와
새 JAR를 함께 넣지 않는다. 운영 서버 파일 변경·업로드·재시작은 수행하지 않았다.

적용 후에는 동일 장소·시야·해상도에서 전경 플레이 프레임 시간을 비교하고,
두 디스플레이가 페이지를 불러오거나 이동할 때 커서가 계속 잡혀 있는지 확인한다.
메뉴 열기와 Alt+Tab 때는 정상적으로 커서가 풀려야 한다. 이번 실행에서는
수정본으로 재시작한 뒤의 실제 FPS 및 네이티브 CEF 통합 검증을 수행하지 않았다.
